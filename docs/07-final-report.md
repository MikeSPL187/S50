# 07. Итоговый технический отчёт — Motorola Moto S50 (XT2409-5), сборка W1UI36H.39-25-11-4

Дата: 01.11.2026. Ветка: `ccr-8fd37226-yb83cu`.

## Кратко

* **Исходники точной установленной сборки найдены и доказательно сопоставлены с прошивкой.** Ядро в `boot.img` —
  официальный Google GKI `android14-6.1-2025-12_r29` (6.1.157, build 16012876); vendor-модули — Motorola
  `MMI-W1UI36H.39-25-11-4`. Пересборка из исходников дала ядро с идентичной строкой релиза, размером Image и
  раскладкой секций, KMI-совместимое со всеми 498 стоковыми модулями, и **побайтно идентичный** стоку машинный
  код модулей `scheduler.ko`, `cpufreq_sugov_ext.ko`, `mtk_core_ctl.ko`.
* **Политика CPU на этом телефоне живёт в vendor-модулях MTK, а не в ядре `boot.img`.** Поэтому `boot.img` не
  меняется; изменения внесены в `cpufreq_sugov_ext.ko`.
* **Реализованы 2 патча** (исправление порядка проверки rate limit; переключатель iowait-буста, по умолчанию как в
  стоке). Оба проходят KMI-gate, сохраняют все экспортные CRC, имеют runtime-переключатели.
* **Честная оценка эффекта:** на штатных настройках PowerHAL ожидаемое изменение UX/энергии **близко к нулю**.
  Проект даёт проверенную основу и инструменты, а реальный выигрыш возможен только через измеренные эксперименты.
* **На телефоне ничего не выполнялось и не прошивалось.** Измерений на устройстве нет — они ожидают исполнения.
* **Готовность к установке:** артефакт собран и проверен офлайн; ставить его имеет смысл только после базовых замеров
  стока и вашего явного решения (см. «Е»).

## А. Устройство и архитектура

См. [00-facts-and-gaps.md](00-facts-and-gaps.md), [02-architecture.md](02-architecture.md),
[results/firmware/inventory.md](../results/firmware/inventory.md).

* MT6878 (Dimensity 7300): 4 малых (`capacity-dmips-mhz` 267) + 4 больших (1024) ядра, два кластера cpufreq
  (policy0, policy4).
* AVB: vbmeta (RSA2048, rollback index 27) хэширует `boot/init_boot/vendor_boot/dtbo`, hashtree для `vendor_dlkm` и
  др.; `KERN_PROT_META` фиксирует раскладку секций ядра (`_stext/_etext/__init_begin`) — любое своё ядро
  потребовало бы пересчёта этого свойства.
* Решения о размещении задач и частотах принимают `scheduler.ko` (42 vendor hooks), `cpufreq_sugov_ext.ko`,
  `moto_sched.ko`, FPSGO; режимы задаёт userspace (PELT×4, uclamp-бусты, PowerHAL-сценарии, MGLRU, zram lz4).
* «Проблемы оригинального ядра»: объективный дефект найден один — rate limit `sugov_ext` мог задерживать
  применение новых freq_qos-лимитов и рост DL (патч 0001); ещё одно наблюдение (глобальный `wl_cnt_cached`)
  зафиксировано без патча. Системных проблем UX без замеров утверждать нельзя.

## Д. Безопасный способ установки (подготовлен, не запускался)

[06-safety-and-rollback.md](06-safety-and-rollback.md):
`00` диагностика → `20` резервная копия + сверка с телефоном (`vbmeta.digest`, `/proc/version`, `init_boot`,
dm-verity) → `10` базовые замеры → `30` предполётная проверка → `40` установка (2 раздела слота A, фраза
подтверждения, возврат в загрузчик без автозагрузки) → `90` откат (в т. ч. при автопереключении на слот B).
GPT/preloader/lk/nvdata/efuse/modem/userdata/слот B не затрагиваются; загрузчик не блокируется; OTA требует
предварительного отката.

## Е. Финальная оценка

| Вопрос | Ответ |
|---|---|
| Что действительно улучшено | Корректность `sugov_ext` (0001); появилась возможность измерить iowait-буст (0002). Измеримое улучшение UX/автономности **не доказано** и на стоковых настройках не ожидается. |
| Главный результат | Доказанная связь «исходник ↔ прошивка», воспроизводимая сборка, KMI- и репро-гейты, безопасный конвейер упаковки и отката, инструменты замеров. Это необходимая база для любых дальнейших изменений. |
| Компромиссы | Установка меняет `vbmeta.digest` и блокирует инкрементальные OTA до отката; vbmeta подписан не ключом OEM: заводская цепочка доверия Motorola для этого раздела не сохраняется (на unlocked/ORANGE загрузка допускается, dm-verity остаётся включённым). Аварийное восстановление проверено только на имитаторе fastboot. |
| Что осталось проверить на телефоне | Диагностика (фактические rate limits, OPP, cpuidle, zram, PSI); базовые замеры стока; работу SIM/Wi-Fi/BT/камер ещё на стоке; затем A/B. Гипотезы 2–3 из 00-facts-and-gaps (fastbootd/vbmeta) проверяются самой установкой с безопасной остановкой. |
| Готов ли к установке | **Технически готов как эксперимент** (все офлайн-гейты пройдены). **Не рекомендуется ставить до** получения базовых замеров стока и до проверки аппаратных функций на стоке — иначе нельзя будет ни оценить эффект, ни отличить проблемы ядра от последствий прошлой прошивки. |

## Ж. Изменения после внешней рецензии (01.11.2026)

| Замечание | Оценка | Что сделано |
|---|---|---|
| `90-restore-stock.sh` не требует `current-slot=a` | верно | останов при слоте ≠ a; явный режим `--set-active-a` (слот A активируется до входа в fastbootd); запуск из загрузчика или fastbootd |
| Автоматическая перезагрузка после записи | верно | `40` и `90` возвращают телефон в загрузчик, показывают слоты; система загружается только после ввода `BOOT` |
| vbmeta подписан своим ключом ≠ цепочка доверия Motorola | верно, но это не дефект, а неустранимая цена любой модификации (ключа OEM нет); было указано в 06 | формулировки уточнены в `40` и 06 |
| Восстановление не проверено на реальном телефоне; копия — из пакета | верно | признано открытым риском (06, раздел 7); чтение разделов без root невозможно — `fastboot fetch` запрещён на user-сборках |
| Без root эксперименты с переключателями невозможны | верно | добавлена диагностика механизма загрузки модулей (`23-module-loading.txt`) для проверки пути через `modules.options` (05, раздел 3) |
| (найдено мной) одного `vbmeta.digest` недостаточно при ORANGE | исправлена собственная переоценка | проверка соответствия расширена: `/proc/version`, `ro.bootimage.build.date.utc`, `ro.boot.veritymode`, слот |
| (найдено мной) откат не учитывал автопереключение на непригодный слот B | исправлено | см. первую строку; добавлено в риски |

### Рекомендуемые следующие шаги

1. Запустить `scripts/device/00-readonly-diagnostics.sh` и прислать архив результата.
2. Выполнить `scripts/device/20-backup-stock.sh` (без root, ничего не пишет в телефон).
3. Проверить аппаратные функции на стоке (раздел 5 плана испытаний).
4. Снять базовую линию: `10-baseline-profile.sh stock-run1` (и повторы), отдельно `sustained`.
5. По данным диагностики решить: ставить ли эксперимент, нужен ли root для U1–U5, какие гипотезы приоритетны.
